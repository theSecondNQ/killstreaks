# 遥控视角、热成像与 GD656 提示修订

适用版本：NeoForge 1.21.1 `1.2.0.4361`、Forge 1.20.1 `1.2.0.4365`。

## GD656 遥控提示

Forge 实例日志记录 `HudElementManager.renderOverlay(GuiGraphics, float)` 的 `NoSuchMethodException`。安装的 GD656 1.3.2 实际使用 `onRenderGuiOverlay(GuiGraphics, float, boolean)`，第三项由它自己的 Forge 事件适配器在到达 `player_list` 叠层时置为 true。

兼容桥优先使用旧版入口，缺失时选择上述三参数入口；遥控接管绘制时每帧仅调用一次。配置查询也同时兼容 `getElementConfigWithFallback` 与新版 `getElementConfig`。继续由 GD656 自身负责字体、图标、动画、预设和提示计时，不重新派发外部 HUD 事件。

## 热成像场景合成

遥控 HUD 在普通 GUI 事件派发前接管绘制，旧热成像只订阅 `RenderGuiEvent.Pre`，因此整幅场景的合成没有执行；NeoForge 旧实体材质替换仍会把生物画白，与用户报告的“实体变白但场景没有变化”相符。

`RemoteHud` 现在于任何 HUD 绘制之前直接调用 `ThermalVision.compose`，F1 隐藏界面时也合成。原 GUI 事件作为备用入口，`ready` 标记保证同一帧只合成一次。地形、天空和光影输出转换为冷灰色，可见生物遮罩显示为热白色，文字及其他 HUD 保留原色。

NeoForge 改用附加层采集模型轮廓，移除全局实体缓冲区白色材质替换。遮罩依旧使用场景深度和可见性判断；无畏装甲轮廓单独采集，共用渲染器只注册一次附加层。现有 Mixin 类保留仅用于无畏装甲的原皮肤局部隐藏，不修改资源配置文件。

## 炮艇摄像机交接

远处实体的原版配对受地形批次是否已发送限制，而遥控状态消息可能提前到达。原客户端找不到实体时直接返回，入场动画却仍继续计时，摄像机因而留在玩家身上。

跟踪注入只对当前操作者自己的遥控实体提前调用原版 `ServerEntity.addPairing`，使用原版 `seenBy` 集合去重，正常的实体生成、元数据和后续同步消息仍由原版负责。其他实体和其他玩家继续原有距离及区块规则；遥控结束后恢复普通跟踪。没有手工生成副本或改写玩家本体位置。

客户端在确认实体存在且摄像机已绑定前保持黑屏、暂停入场动画。绑定后继续原有过场和左翼下方炮手挂点；断线、死亡、维度切换和缺失实体超时仍走原有清理路径。

## 交付范围

修订同步两个加载器源码及 NeoForge 镜像，不增加或同步资源，不改版本号。依据现有故障日志、安装 JAR 的公开方法和 Minecraft 源码定位；编译与发行包完整性记录见 `build/logs/remote-hud-thermal-camera-*.log`。本次未新增或运行自动化测试，也未启动世界进行实机或光影组合验证。
