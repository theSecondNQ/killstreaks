# Java 编码约定

沿用本次用户修改的 `DroneDeploymentSounds`、`NativeAudio` 写法。根目录 `.editorconfig` 提供基础缩进、编码和换行设置。

## 排版

- 使用 UTF-8、LF 换行、四空格缩进；Java 行宽以 120 字符为目标。
- 方法体、控制流程、非空 lambda 展开；每条语句独占一行，方法之间留一行。
- 左花括号放在声明末尾；`catch` 另起一行。单条提前返回可以不加花括号，返回语句另起一行。
- 调用链较长时分行，保留已有的有意义分段。`switch` 的 `case` 比 `switch` 多缩进一级。
- 空的私有工具类构造器可写成 `private ClassName() {}`。它用于禁止实例化，应保留。

## 命名与组织

- 类名使用大驼峰；方法、参数和局部变量使用小驼峰；常量使用大写加下划线。
- 玩家、世界、实体、图形上下文等参数使用 `player`、`level`、`unit`、`graphics` 等具体名称。
- 坐标、向量分量和短循环索引可保留 `x/y/z`、`i/j`；复杂状态应给出明确含义。
- 类型使用显式导入，移除未用导入；按工程类型、Java 标准库、外部库、静态导入分组。
- 沿用现有包分类。方法默认保持内部可见，仅为跨包调用提供必要的公开接口。
- 为类的职责、状态转换、单位换算和不直观的兼容限制写简短说明；保留原有资源来源与坐标约定。

## 冗余代码清理

- 按具体方法签名核对调用和方法引用，区分重载；不能只搜索方法名称。
- 检查事件订阅、Mixin 配置与注入、接口及父类实现、反射、序列化和记录访问器。
- 删除未使用入口后，再检查其辅助方法、旧模型构造和遗留字段。
- 每轮删除后重新进行编译器引用分析；交付前构建生产 JAR 并核对资源和归档。
- 将临时分析、构建结果放在 `build`，备份及历史发行放在工程外。

4.30.0 清理的具体删除清单见 [CODE-CLEANUP.json](CODE-CLEANUP.json)。

## 模块设计

- 同一状态的存储、迁移及约束集中管理；调用方通过领域操作改变状态，避免自行拼接存储键或读后再写。
- 用明确的渲染阶段、重置类型及溢出策略表达不同操作，避免多层布尔参数组合。
- 固定资源的解析结果跨帧复用；增加缓存时同步明确重载入口、线程及原图／GPU 资源的释放责任。
- 只有实际存在多种实现时才增加替换接口。仅转发调用且没有隐藏规则的包装，应合并到实际实现。
- 重构入口、事件及资源依赖时，按具体方法签名核对引用；沿用 [模块设计](ARCHITECTURE.md) 记录的存档及网络约束。
